# Git e GitHub para o Felipe — do zero, sem enrolação

> Você não precisa decorar nada. Precisa de **três imagens mentais** e de
> confiar no `forge` (que já faz tudo certo para você). Este documento existe
> para você entender **o que** cada passo faz.

## As três imagens mentais

### 1. Commit = fotografia 📸
O git tira uma **foto** do estado dos arquivos e guarda com uma *legenda*
(a mensagem do commit). Fotos antigas nunca somem — dá sempre pra voltar.

```
foto 1 ── foto 2 ── foto 3 ── ...   (a sequência de fotos é a "linha do tempo")
```

Você nunca tira uma foto *para perder* — então commitar com frequência é bom.
`forge commit "mensagem"` = tira a foto.

### 2. Branch = linha do tempo paralela 🌿
Uma **branch** é uma linha do tempo alternativa. Você segue nela sem mexer na
linha principal (`master`). Quando está satisfeito, **merge** = juntar as duas
linhas:

```
master:   ──●──●────────●────────●
                  \      / (merge)
forge/x:           ●──●──
```

Nós FAZEMOS ISSO SEMPRE: você trabalha na `master` (linha principal); eu edito
numa branch `forge/<nome>` (linha paralela). Sua linha nunca é tocada na
metade do caminho.

### 3. GitHub = nuvem de backup + mesa de aprovações ☁️
- **push** = enviar suas fotos pra nuvem.
- **pull / fetch** = baixar fotos da nuvem.
- **Pull Request (PR)** = *"pedido de aprovação"*. É um convite: "olha essa
  mudança, aprova?" — você pode ver exatamente o que mudou, comentar, e só
  então **mergear**.
- **tag** = etiqueta que marca uma versão (`forge/v2026-10-01`). É um ponto
  fixo na história, pra sempre — voltar pra ele é trivial.

## O fluxo que usamos — traduzido

| Comando `forge` | O que acontece por baixo (git) | Tradução |
|---|---|---|
| `forge status` | `git status`, `git tag --list` | "mostra o painel: o que tá diferente? quais versões existem?" |
| `forge new pizza` | `git switch -c forge/pizza master` | "abre a linha do tempo `forge/pizza` a partir do topo da master" |
| `forge commit "m"` | `git add -A && git commit -m "m"` | "tira a foto com legenda" |
| `forge push` | `git push -u forge forge/pizza` | "envia as fotos pra nuvem" |
| `forge pr "t"` | `gh pr create --base master ...` | "manda o pedido de aprovação pra master" |
| `forge release` | `gh pr merge ...`, `git tag forge/v…`, `git push` | "você aprovou: junta na master, etiqueta a versão e publica" |
| `forge rollback forge/vX` | `git reset --hard forge/vX` | "volta pra etiqueta anterior (a nova continua salva na nuvem)" |
| `forge sync` | `git fetch forge`, comparação | "a master local está igual à nuvem?" |

## O que NUNCA fazer (e por quê)

- ❌ **Editar direto na master e commitar sem pedir.** É a linha que você usa;
  qualquer erro vira sua versão do dia a dia. Sempre nasce em branch.
- ❌ **`git push --force`.** Sobrescreve história que já foi pra nuvem —
  destrói versões. Só com seu pedido explícito na hora.
- ❌ **Commits com mensagem vazia ou em inglês.** Toda foto precisa de legenda
  clara, e legenda é em português para você ler depois.
- ❌ **Worktree sujo.** Fotografias só de estado limpo — senão a foto sai com
  lixo dentro.

## Dica de ouro

Você não precisa saber os comandos de cor: o `forge` roda eles pra você e
**explica o que fez** a cada passo. Quando um dia quiser fazer algo fora do
script, pergunte na sessão — a gente faz junto e você aprende na prática.
